## 修复 website-winui3 在 Cloudflare 上 N 级路径 404 问题

### 根因
website-winui3 是 SPA（vue-router `createWebHistory` history 模式，`vite.config.ts` 中 `base: '/'`），构建产物只有 `dist/index.html` 一个 HTML 入口。Cloudflare Pages 静态托管默认不做 SPA 回退：直接访问 `/guide/x`、`/download/thanks` 等 N 级路径时，静态文件不存在 → 返回硬 404。

### 改动（2 个文件）

**1. 新建 `website-winui3/public/_redirects`**（核心修复）
```
/* /index.html 200
```
- 这是 Cloudflare Pages 标准的 SPA 回退规则：所有未命中真实静态文件的路径都会被重写为 `/index.html`，由前端路由接管渲染。
- Vite 构建时会把 `public/` 原样复制到 `dist/` 根目录，因此重新部署即可生效，无需改构建配置。
- 已有的真实文件（如 `/tutorials/xxx.png`、`/comparison/xxx`）仍优先命中，不受影响。
- 该文件同样兼容 Cloudflare Workers Static Assets（`_redirects` 受支持），无论你当前用哪种方式部署都能生效。

**2. 修复 `website-winui3/src/site/router.ts` 第 23 行 catch-all 路由 bug**
```ts
// 改前：redirect: '/home'  —— /home 并非已注册路由（首页是 '/'），未知路径会再次命中 catch-all 形成无限重定向，vue-router 中止导航导致白屏
// 改后：
{ path: '/:pathMatch(.*)*', redirect: '/' }
```
保留"未知路径回首页"的原有意图，但指向真实存在的首页路由。

### 验证
- 在 `website-winui3/` 下执行 `npm run build`，确认 `dist/_redirects` 已生成且内容正确。
- 若本机有 wrangler，可 `npx wrangler pages dev dist` 本地模拟 Cloudflare 验证 `/guide/x` 不再 404（无网络/无登录则跳过，仅做构建产物确认）。

### 部署提示
重新部署 `website-winui3/dist/` 到 Cloudflare（Pages 直传或 Git 集成均自动带上 `_redirects`），之后刷新/直达 `/guide/x`、`/download/thanks` 等任意层级路径都会正常返回 index.html。

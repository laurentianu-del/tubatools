## 目标

参照 https://github.com/PLFJY/ContextMenuMgr 的核心原理，为图吧工具箱新增一个 **NativeAOT 编译的独立常驻后端 `TubaWinUI3.BackEnd`**（流氓软件拦截器），并为主程序增加「主动拦截」开关 + 审核界面。

## 核心原理（源自 ContextMenuMgr）

ContextMenuMgr 的杀手锏不是「手动开关」，而是 **「先拦截，再审核」+ 期望状态持续纠偏**：
1. 监控右键菜单注册表根（见下方清单），扫描出所有第三方右键项，解析出所属可执行文件/CLSID。
2. 新出现的项目 **立即禁用**（写入 `Shell Extensions\Blocked` CLSID 列表或 `LegacyDisable`），放入「待审核」队列，持久化期望状态。
3. **持续轮询纠偏**：即使第三方软件删除后再重新写入同名注册项，后端每次轮询检测到期望状态为「禁用」都会自动再次禁用，防「删了又写」。
4. 首次运行以当前机器状态为**基线**（不误杀存量项目）；只在基线白名单之外的「新增」项上动作。

## 一、新增项目 `TubaWinUI3.BackEnd`

**目录** `TubaWinUI3.BackEnd/`，SDK 风格控制台项目，加入 `TubaWinUi3.sln`。

**`TubaWinUi3.BackEnd.csproj`** 关键属性：
- `OutputType=Exe`、`TargetFramework=net10.0-windows`、`PublishAot=true`（NativeAOT 单文件、无运行时）、`InvariantGlobalization=true`、`SelfContained=true`
- `RuntimeIdentifier` 随构建传入（`win-x64`/`win-arm64`/`win-x86`），`OptimizationPreference=Speed`、`StripSymbols=true`
- `AllowUnsafeBlocks=true`、`Nullable=enable`
- 只依赖 `System.Text.Json`（AOT 编译为源生成，`JsonSerializerContext`）

**主要源码文件**（`Services/` 下）：
1. **`Program.cs`** — 入口：解析 `--config <settingsPath>` 参数，加载配置，启动 `ActiveInterceptMonitor`，挂 `Console.CancelKeyPress`/`AppDomain` 退出钩子做清理。
2. **`ContextMenuRoots.cs`** — 右键菜单监控根清单（静态数组，与 ContextMenuMgr / 现有 RogueCleaner 的 Roots 一致）：
   - `Software\Classes\*\shell` / `*\shellex\ContextMenuHandlers`
   - `AllFilesystemObjects`、`Directory`、`Directory\Background`、`DesktopBackground`、`Drive`、`Folder`、`lnkfile`、`exefile`、`Unknown` 各自的 `shell` / `shellex\ContextMenuHandlers`
   - 支持 `HKCU` + `HKLM` × `Registry64`/`Registry32` 视图（避免误动 WOW6432Node）。
3. **`ContextMenuScanner.cs`** — 用 `RegistryKey.OpenBaseKey` 枚举这些根下的子键，解析：子键名、`MUIVerb`/默认值、`command` 默认值、`Icon`、`ExplorerCommandHandler`、`shellex` 的 CLSID；并解析 CLSID → `InprocServer32`/`LocalServer32` 所属 exe/dll 路径（ContextMenuMgr 的 GuidMetadataCatalog 手法）。
4. **`BlockEngine.cs`** — 屏蔽/放行原语：
   - 禁用（Shell 扩展）：在 `HKCU`/`HKLM` 的 `Software\Microsoft\Windows\CurrentVersion\Shell Extensions\Blocked` 写入 CLSID 值（值内容「由流氓软件克星主动拦截禁用」）。
   - 禁用（Shell 命令 verb）：在 `shell\<verb>` 子键写入 `LegacyDisable`。
   - 放行：删除对应值；所有写操作先做**快照备份**到 JSON（可回滚）。
5. **`ActiveInterceptMonitor.cs`** — 轮询引擎（间隔默认 10s，可配置）：每轮扫描全量 → 与持久化状态对比 → 分类「新增/恢复/已删/已放行」→ 对期望状态为「禁用」的新增/恢复项执行屏蔽并写事件 → 对已被放行的项停止屏蔽。**首次启动建立基线白名单**（不拦截存量）。任何读写前做**指纹比对**，仅在有实际变化时写注册表（减少写放大）。内部有“已知最近被自己写入的键”集合，抑制对自身纠正动作的误报。
6. **`StateStore.cs`** — 持久化期望状态（`dataDir/active_intercept/state.json`）：每个条目含 `Id`(hive|view|subkey)、`Clsid`、`DesiredState`(Blocked/Allowed)、`FirstSeenUtc`、`Source`、`ExePath`。
7. **`EventLog.cs`** — 拦截事件追加写入 `dataDir/active_intercept/events.jsonl`（每条含时间、项目、CLSID、动作=Blocked/Allowed）。主程序从这里读取展示。
8. **`BackendConfig.cs`** — 从 `--config` 读：`PollIntervalSeconds`、`DataDir`、`LogFile`。
9. **`NativeAotJson.cs`** — `[JsonSerializable]` 源生成上下文（保证 AOT 可用）。

**UI 线程/消息循环**：NativeAOT 控制台程序无需 WinUI，`Task.Delay` 轮询即可；AOT 下 `RegistryKey`、`File` 读写均为可用 API。

## 二、主程序集成

### 1. 后端进程管理 — `TubaWinUi3.WinUI3/Services/ActiveIntercept/ActiveInterceptService.cs`（新）
- 静态服务（与现有 EnergyStarService 同风格），持有 `Process` 句柄。
- `Start()`：定位 `Path.Combine(ToolCatalog.AppDirectory, "TubaWinUi3.BackEnd.exe")`（未打包主路径；MSIX 时回退 `AppContext.BaseDirectory`），传 `--config "<dataDir>\active_intercept\config.json"`，`UseShellExecute=false`（可捕获退出码），`WindowStyle=Hidden`，`EnableRaisingEvents=true`，注册 `Exited` 自动重启/置位。
- `Stop()`：`CloseMainWindow` 或 `Kill()`。
- `IsRunning()`：进程存活判断；若开关开但进程不在，自动拉起（防误杀/崩溃后自愈）。

### 2. 设置开关 — `SettingsPage`
- `SettingsPage.xaml`：仿 `SettingsHardwareFitScreenCard` 增加 `SettingsActiveInterceptCard`（图标 `\uE899`，标题「主动拦截流氓软件」，副标题说明「后台常驻监控右键菜单注册项，自动屏蔽新增的第三方右键菜单，可在『流氓软件的克星』中审核」+ `ActiveInterceptToggle`）。
- `SettingsPage.xaml.cs`：`InitActiveInterceptToggle()`（读 `AppSettings.GetBool("ActiveInterceptEnabled")`）、`ActiveInterceptToggle_Toggled()`（写设置并调用 `ActiveInterceptService.Start()/Stop()`）；把新键加入 `SettingKeyToExpander` / `SettingKeyToCardName` 字典。

### 3. 启动时自动拉起 — `App.xaml.cs`
- `RunStartupSequenceAsync()` 中加入：`if (AppSettings.GetBool("ActiveInterceptEnabled")) ActiveInterceptService.Start();`（已运行则跳过）。

### 4. 审核界面 — 并入「流氓软件的克星」页
- `RogueCleanerPage.xaml`：新增 `NavigationViewItem NavActiveIntercept`（Tag="activeintercept"，「主动拦截」）。
- `RogueCleanerPage.xaml.cs`：`OnNavigatedTo`/`Nav_SelectionChanged` 处理 `"activeintercept"`，切换 `ActiveInterceptPanel` 可见性。
- 新增 `RogueCleanerPage.xaml` 中 `ActiveInterceptPanel`：读 `events.jsonl` 的列表视图 + 每行操作按钮（**放行**=设置期望状态 Allowed 并解除屏蔽、**重新屏蔽**、**删除记录**）。状态栏显示后端运行状态（运行中/未运行）+ 统计（已拦截 N 条）。后端运行时通过 `AppSettings.SettingChanged` 或手动刷新按钮重新加载。

### 5. 打包分发
- `TubaWinUi3.csproj`：参照现有 `GenerateBundledToolCache` 模式，新增 **`PublishBackend` target**（`BeforeTargets="GetCopyToPublishDirectoryItems"`，仅 `ExcludeToolsFromPublish != true` 且目标 RID 与宿主架构兼容时执行）：`dotnet publish TubaWinUi3.BackEnd -c Release -r $(RuntimeIdentifier) -o <publishDir>\BackEnd`，然后把 `TubaWinUi3.BackEnd.exe` 以 `ContentWithTargetPath` 登记到发布输出根（`TargetPath="TubaWinUi3.BackEnd.exe"`）。
- `build-release.yml` 无需改动（该 target 会在 `dotnet publish` 时自动触发）；`build-setup.ps1` 打包时自然包含（位于输出根）。

### 6. 测试
- `TubaWinUi3.Tests`：新增 `ActiveInterceptStateTests.cs`，用 temp 目录 + 注入测试（参照 `ToolCacheServiceTests` 的 temp-dir 模式）测试状态文件读写、期望状态序列化、事件追加。注册表屏蔽逻辑本身因需管理员权限不纳入常规单测（对齐现有 RogueCleaner 处理）。

## 三、关键约束与安全

- **对齐现有约定**：字符串硬编码中文；命名空间 `TubaWinUi3.BackEnd`；static 服务无 DI。
- **权限**：主程序 unpackaged 模式已自提权为管理员，后端子进程继承管理员 → 可写 HKLM。MSIX 模式后端在包内以 full-trust 运行（manifest 已声明 `runFullTrust`）。
- **防误杀**：首启基线白名单；只拦截「新增」项；`shellex` 无 CLSID 的项只读不动作。
- **生命周期**：独立常驻进程，主程序退出不杀；用户关闭开关时 `Stop()`。
- **不提交**：`bin/`、`obj/`、`.pfx`、`.cer`（后端同样遵守）。

## 四、验证方式

1. `dotnet build`（主程序编译通过）
2. `dotnet publish TubaWinUi3.BackEnd -c Release -r win-x64`（验证 NativeAOT 单文件生成、可运行，`TubaWinUi3.BackEnd.exe --help` 退出码正常）
3. `dotnet test`（新状态测试通过）
4. 手动：开启开关 → 手工在 HKCU\Software\Classes\*\shell 下建一个测试 verb → 观察被自动屏蔽且写入 Blocked/LegacyDisable → 在「流氓软件的克星/主动拦截」页看到记录并可放行/重屏蔽 → 关开关进程退出。

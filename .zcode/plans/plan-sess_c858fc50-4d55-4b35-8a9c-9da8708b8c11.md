## Fix: 内置工具独立窗口不跟随应用主题

### Root cause
`TubaWinUi3.WinUI3/Services/BuiltinToolWindow.cs:25-28` — the "独立窗口" mode window host creates a `Window()` and sets a `Frame` as content without applying the app theme. Unlike every other secondary window/dialog in the app (WhatsNewWindow, ScriptRunnerWindow, ErrorWindow, GitHubDownloadWindow, ContentDialogs — all do `RequestedTheme = ThemeService.CurrentElementTheme`), the tool window's content inherits the **system** theme. The title bar is themed correctly (via `BuiltinWindowHelper.ApplyTitleBarTheme`), which is why only the window background/content area looks wrong.

### Change (single file, 2 lines)
In `BuiltinToolWindow` constructor (`TubaWinUi3.WinUI3/Services/BuiltinToolWindow.cs`):

```csharp
var frame = new Frame { CacheSize = 10 };
frame.RequestedTheme = ThemeService.CurrentElementTheme;   // 新增：与其它独立窗口一致，跟随应用主题设置
frame.Navigate(pageType, parameter);
```

(set `RequestedTheme` on the `Frame` before navigation, so hosted pages pick it up at load).

### Why this is sufficient
- `Frame` is the window's content root; pages that don't set their own `RequestedTheme` inherit it. Grep confirms none of the hosted tool pages (`ToolContentPage`, `PcTutorialPage`, `QuickDeviceCheckPage`, …) set their own theme.
- Fixes both the page background **and** the Mica backdrop tint (Mica adapts to the content's requested theme).
- When the app setting is "跟随系统" (Default), `CurrentElementTheme` returns `ElementTheme.Default` → window correctly follows the system.

### Out of scope (consistent with app-wide convention)
ThemeService only live-updates `App.MainWindow.Content` (no theme-change event); all other secondary windows are themed at creation only. A tool window already open during a theme switch in Settings will keep its creation-time theme — same behavior as every other secondary window, so no extra handling is added.

### Verification
- `dotnet build` (Debug).
- Manual: set 外观 to 深色/浅色 → open a built-in tool in 独立窗口 mode → window content/background matches the app theme; set 跟随系统 → matches system.
- No unit test added: `BuiltinToolWindow` constructs a real `Window` (WinUI runtime, UI thread); the existing xUnit suite covers no window/launcher code, so a test would require new UI-test infrastructure — not worth it for this 2-line fix.

## 目标
提高 AI 助手执行时（多轮 agent 对话、垃圾清理多轮分析、旧版建议+执行助手）的 prompt 缓存命中率，降低输入 token 成本。应用侧与网关侧（openai-proxy-worker，上游 opencode/nvidia 为付费）双管齐下。

## Part A — 应用侧（TubaWinUi3.WinUI3）：解锁上游缓存命中的关键

### A1. 系统提示词去易变化（根因修复）
- `Services/AiAssistantService.cs`：`BuildSystemInfoContext()` 删除「当前时间：{DateTime.Now…}」行（当前时间每分钟变化，而 `AgentSession.EnsureSystemPrompt()` 每次发送都重建系统提示词；系统提示词是最前缀，一变即整段缓存失效）。
- 当前时间改放到**用户消息末尾**（追加在请求最后，对前缀缓存零影响）：
  - `AgentSession.SendAsync`：用户消息改为 `userText + "\n\n（当前时间：yyyy年M月d日 HH:mm）"`；
  - 旧版助手 `ProcessUserMessageStreamAsync` 两处 systemContent 构建处同步把时间拼进 user 消息；
  - `get_system_info` 工具（~543 行）返回内容末尾追加当前时间（工具结果是追加消息，无缓存影响）。
- 效果：同一会话状态下系统提示词字节级稳定 → 每次发送的第一轮请求即命中「系统+全部历史」缓存，只按 miss 价付新增的一条用户消息。

### A2. 缓存命中率可观测性
- `Services/AiService.cs`：`AiChatResponse` 增加 `CacheHitTokens`/`CacheMissTokens`；usage 解析抽成可单测静态方法，兼容 DeepSeek/GLM 的 `prompt_cache_hit_tokens`/`prompt_cache_miss_tokens` 与 Moonshot/Kimi 的 `cached_tokens`；`ChatWithToolsAsync` 解析后填入。
- `Services/Agent/AgentRuntime.cs`：`AgentUsage` 加同名字段，流式 usage 尽力从 OpenAI SDK 读取（AdditionalProperties / InputTokenDetails.CachedTokenCount），读不到为 null 不破坏现状。
- `Services/Agent/AgentSession.cs`：累加并暴露 `TotalCacheHitTokens`/`TotalCacheMissTokens`；`AgentStepGroupSummary` 加字段。
- `Pages/AiAgentPage.xaml.cs`：token 气泡在有条目时显示「X tokens · 缓存命中 Y (Z%)」；步骤组折叠摘要同步。
- 网关会把上游 usage（含缓存字段）透传，所以走默认网关也能看到命中率。

### A3. 单元测试（TubaWinUi3.Tests）
- usage 解析：DeepSeek 风格、`cached_tokens` 风格、无 usage 三种情况。
- `BuildSystemInfoContext()` 不再含「当前时间」；AgentSession 相同状态下连续构建系统内容字节一致。
- `dotnet test` 全量无回归。

## Part B — 网关侧（openai-proxy-worker）：让付费上游的缓存能跨轮命中

### B1. 会话粘性路由（KV sticky，核心）
- 现状：fallback 链 opencode-free → opencode → nvidia，多轮对话中途一旦限流/抖动就换上游 → 新上游看到全新对话，前缀缓存归零；且换到不同模型（deepseek-v4-flash-free / deepseek-v4-flash / deepseek-ai/deepseek-v4-flash）行为也不一致。
- 方案：用稳定前缀做会话指纹 `convId = sha256(route.model + messages[0].role+content + JSON.stringify(tools))`（系统提示词稳定后指纹跨轮不变）；KV 存 `sticky:<convId> → provider`（复用 QUOTA KV 命名空间，TTL 默认 30 分钟，`STICKY_TTL` 可配）。请求时优先走粘性 provider，失败则按原链降级并把粘性键更新为成功者；`STICKY_ROUTING=0` 关闭。
- 收益：同一会话多轮请求钉在同一上游 → 上游支持前缀缓存时（opencode 付费链路大概率是 DeepSeek 官方，支持自动缓存）跨轮命中；即使不支持，也消除中途换上游导致的缓存全失。

### B2. 转发字节稳定性
- 已审计 `buildMessages`/`requestBody` 重建为确定性序列化（键序固定），**无需改动**，保持现状即可。

### B3. 响应缓存（可选旋钮，默认关）
- `RESPONSE_CACHE_TTL` 默认 0；>0 时对完全相同的**非流式**请求（如 TestConnection、取消后原样重发同一条消息）用 KV 直接返回，省一次上游调用。多轮 agent 请求体每次不同，收益有限，作为可选开关写在 wrangler.toml 注释里。

### B4. 管理面统计 + 文档
- `recordUsage` 把 `prompt_cache_hit_tokens` 单独记账，`GET /v1/admin/usage` 展示每日缓存命中 token，直接看到省钱效果。
- wrangler.toml 补 `STICKY_ROUTING`/`STICKY_TTL`/`RESPONSE_CACHE_TTL` 注释；根路径信息 JSON 同步。
- 把指纹/粘性选择逻辑抽成纯函数，加一个 `node --test` 最小单测（确定性 + 跨轮同指纹），`package.json` 加 `test` 脚本。

## 验证
- `dotnet build` + `dotnet test`（应用侧）。
- `node --test`（worker 单测）。
- 手动：用 DeepSeek 官方 API 连续对话观察 token 气泡命中占比上升；`/v1/admin/usage` 看每日缓存命中 token。
- 网关部署（`wrangler deploy`）由你确认后另行执行，不包含在本任务中。

## 不做的事
- 网关不伪造模型侧前缀缓存（技术上不可能），只做 B1–B4 中可行的优化。
- 不加 `cache_control` 等请求参数（所用提供商均为自动缓存）。
